# 后台录制修复与验收（2026-09-07）

## 原因与修复边界

eframe 0.35 在窗口被遮挡、最小化或隐藏时可能跳过 `App::ui`，但仍调度 `App::logic`。此前 `show_workbench` 在绘制时才接收 USB 消息、提交录制和安排下一轮处理，后台停止绘制也就停止消费采样。

本次将运行逻辑统一放入 `update_runtime`，由 `App::logic` 调用。界面只负责显示和操作；采样期间 16ms 调度，空闲 100ms，积压立即请求下一轮，保持单轮 64 条消息上限。单实例唤醒也在此处理。

未修改 USB/PD 核心、设备时间积分、录制状态机、偏好字段、依赖版本和 CSV/Parquet 23 列契约。系统主动睡眠与 USB 断线仍走原恢复流程。

## 自动回归

- `logic_records_without_painting_across_segment_boundaries`：不调用 UI，驱动真实逻辑回调，输入 61 秒已知采样；检查累计能量/容量、两次 30 秒分段、三个落盘 CSV 共 123 点且每个文件 23 列。
- 同一测试检查空队列重复调用不重复累计、手动暂停不会自动恢复、低功率自动暂停及恢复阈值以上自动继续，覆盖设备序号回绕。
- `verify_background_recording_artifact`：通过 `KM003C_VERIFY_RECORDING` 指定验收导出文件，调用现有导入器检查逐点序号、元数据点数/有效时长/累计量一致，并报告最大采样间隔。
- 格式检查、完整测试及 `cargo clippy --locked --all-targets -- -D warnings` 通过。
